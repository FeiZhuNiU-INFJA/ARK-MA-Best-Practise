## 一、输入契约（Phase A+B 产出，`hot_topics_normalized.xlsx`）

| 字段 | 说明 |
|---|---|
| `row_id` | 唯一行标识，全局不重复 |
| `platform` | 平台（微博/抖音/B站/知乎） |
| `title` | 热点标题 |
| `hottopic_desc` | 热点描述（部分平台为空） |
| `hot_index` | 平台原始热度指数 |
| `heat_score` | 标准化热度分（log1p+P1/P99百分位归一化，见 `phases/B_normalize_v2.md`算法说明） |
| `hotpost_time` | 发布时间（datetime格式） |
| `hottopic_url` | 原始链接 |
| `hot_thumbnail_url` | 缩略图链接 |
| `week_num` | 周次编号 |

## 二、合并宽表字段（Phase D 产出，`wide_table_{mode}_r{N}.xlsx`，28列）

按pipeline两批次分组，列序：基础→C0(第一批)→C3(第一批)→C2(第二批)→R1~R5(第二批)。

| 分组 | 列数 | 字段 | 来源 |
|---|---|---|---|
| 基础字段 | 9 | 序号/平台/热点标题/热点描述/平台热度值/标准化热度分/发布时间/链接/周数 | `hot_topics_normalized.xlsx` |
| C0 基础事实层 | 7 | 商业实体/热点驱动词/行业归属/营销触发方式/营销维度/是否营销可用/判断说明 | DataHub C0结果展开 |
| C3 节点标注 | 1 | 提取节点（仅保留"是否节日营销=是且是否窗口期内=是"的节点名） | DataHub C3结果派生 |
| C2 事件合并 | 1 | 事件簇名 | blueai-canonical-event-registry |
| R1 平台玩法 | 2 | 是否平台玩法/平台玩法说明 | DataHub R1结果展开 |
| R2 商业合作 | 2 | 是否商业合作/合作动态说明 | DataHub R2结果展开 |
| R3 风险预警 | 2 | 是否风险预警/风险判断说明 | DataHub R3结果展开 |
| R4 营销发现 | 2 | 是否营销发现/营销发现说明 | DataHub R4结果展开 |
| R5 消费者行为 | 2 | 是否消费者行为/消费者行为说明 | DataHub R5结果展开 |

R1~R5/C2 只覆盖 C0 筛选后的"营销可用"子集行，其余行该批次字段为空，非缺陷。
