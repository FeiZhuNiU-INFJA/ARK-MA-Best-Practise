## 核心原则

1. **数据先行**：每段洞察先呈现数据（数字 + 维表），再写解读文字
2. **反直觉优先**：同等数据量的洞察，优先写"意外发现"而非"符合预期"
3. **具体胜于抽象**：用"食品零食以 81.6 分的热度值中位数居 TOP10 之首"，不用"食品行业热度较高"
4. **禁止编造**：所有数字必须来自合并宽表，不得估算或推断

## 行业分布洞察写法框架

```
上周营销可用热点共覆盖 {N} 个行业，{行业A} 以 {条数} 条热点占据声量首位，
是第二位{行业B}（{条数} 条）的 {倍数} 倍；
但声量领先并不意味着「每条更热」——{行业C} 以 {分数} 分的热度值中位数居 TOP10 之首，
{N} 条热点背后是 {驱动事件}，属于「条数少但每条热度高」的高密度行业。
```

## 禁止行为

- 使用"可能""或许""大概"等不确定表达描述数据
- 在没有 cluster_id 支撑的情况下声称"同一事件跨平台传播"
- 用"热点数"代替"营销可用热点数"（两者含义不同）
- 报告标题使用除 `{period_label}` 之外的日期格式
