## 说明

`pipeline_ab.py` 将 Phase A（取数 + 清洗）和 Phase B（热度标准化）**合并为一条命令执行**。
Agent 调用本 Phase 后，A/B 两步均告完成，可直接进入 Phase C。

## 执行步骤

### Step A-1：读取日期参数

从 `Projects/{PROJECT_DIR}/run_config.yaml` 读取：
```
date_start: {YYYY-MM-DD}   # 建议比目标周再往前 7 天
date_end:   {YYYY-MM-DD}   # 建议比目标周结束日多 1 天
```

> 脚本会自动找最近包含完整 7 天的 ISO 自然周（周一～周日），
> 多取几天余量是为了保证算法有足够数据识别完整周。

### Step A-2：运行 pipeline_ab.py

```bash
python skill/fetch-normalize/pipeline_ab.py \
  --start       "{date_start}" \
  --end         "{date_end}" \
  --project-dir "Projects/{PROJECT_DIR}"
```

**API Key 查找顺序**（脚本内部自动处理，无需手动传入）：
1. 环境变量 `BLUEAI_API_KEY`
2. `~/.claude.json` 中 `crawler-hot-topics-server` 的 `Authorization` 头

脚本非零退出时，立即暂停并将完整 stderr 展示给用户，等待指示。

**常见失败原因**：
- `未找到完整 7 天的 ISO 自然周`：将 `--start` 再往前推 7 天后重试
- `以下平台无数据`：服务端该平台暂无数据，与用户确认是否继续
- `未找到 API Key`：确认环境变量或 `~/.claude.json` 配置是否正确
- `基准文件不存在`：检查 `skill/fetch-normalize/references/平台热度基准_2026.json`

**可选：复用已有原始数据**（调试 / 重跑时使用）

```bash
python skill/fetch-normalize/pipeline_ab.py \
  --start       "{date_start}" \
  --end         "{date_end}" \
  --project-dir "Projects/{PROJECT_DIR}" \
  --skip-fetch
```

### Step A-3：更新 run_config.yaml

脚本成功退出后（退出码 0），从脚本 stdout 提取数值并更新：

```yaml
status:
  current_phase: "sample"   # A+B 均已完成，下一步是分层抽样（见 prompt/03_阶段_抽样.md）
  a_output_file: "Projects/{PROJECT_DIR}/01_原始数据/hot_topics_raw.xlsx"
  b_output_file: "Projects/{PROJECT_DIR}/02_标准化/hot_topics_normalized.xlsx"
  a_clean_rows:  {stdout 中 "[A-3] 已输出" 后的行数整数}
  b_total_rows:  {stdout 中 "[B-2] 已输出" 后的行数整数}
```

> 2026-09-20 修正：原值写 `"C_annotation_sample"`，该值**不在 `current_phase` 合法值域内**
> （值域见 `prompt/run_config契约.md`）；原注释「直接跳到 C」也是抽样步骤长期缺失的根源 ——
> A+B 之后还有一步分层抽样，test 模式下不可跳过。

### Step A-4：向用户展示摘要

从 stdout 提取统计数据，展示：

```
Phase A+B 完成

周次：{week_num}（{iso_label}）
原始记录数：{由 "[A-1] 取数完成：N 条" 提取}

清洗结果（hot_topics_raw.xlsx）：
  总行数：{a_clean_rows}
  各平台明细（来自 [A-3] 校验通过摘要）：
    微博：{n} 行，热度缺失 {n} 条
    抖音：{n} 行，热度缺失 {n} 条
    B站： {n} 行，热度缺失 {n} 条
    知乎：{n} 行，热度缺失 {n} 条

热度标准化（hot_topics_normalized.xlsx）：
  各平台分数分布（来自 [B-2] 校验通过摘要）：
    微博：均值 {x}，最高 {x}，最低 {x}
    抖音：均值 {x}，最高 {x}，最低 {x}
    B站： 均值 {x}，最高 {x}，最低 {x}
    知乎：均值 {x}，最高 {x}，最低 {x}

进入 Phase C 三路并发标注（小样本 500 条）...
```

**热度标准化警告处理**（仅在 stderr 含 "最高分" + "≤90" 时触发）：
```
⚠ Phase B 警告：{平台} 最高分仅 {x}，低于校验阈值 90。
A) 接受现有结果，继续流程（适用：本周热点整体降温属正常现象）
B) 检查热度基准参数是否过期，暂停等待更新
C) 自定义处理（请说明）
请回复 A / B / C。
```
