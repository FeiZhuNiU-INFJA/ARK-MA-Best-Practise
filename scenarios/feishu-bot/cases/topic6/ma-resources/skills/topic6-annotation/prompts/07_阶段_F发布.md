### Step 1：自校验

对 `07_报告/热点报告_{period_label}_v{N}.md` 逐项检查：

| 检查项 | 标准 |
|---|---|
| 章节完整性 | 4个版块标题均存在，均非空 |
| 数字来源 | 报告中出现的数字均可在 `05_合并/wide_table_full_r{N}.xlsx` 中追溯，不出现"约""估计""大概" |

| LLM 痕迹 | 不出现"综上所述""样本量充足""已按判断规则过滤"等工作透明语 |

### Step 2（F-1）：确认报告文件

### Step 3（F-2）：导入飞书（捕获 doc token / url）

```bash
IMPORT_JSON=$(lark-cli drive +import \
  --file "Projects/{PROJECT_DIR}/07_报告/热点报告_{period_label}_v{N}.md" \
  --type docx \
  --folder-token ${FEISHU_HOTREPORT_FOLDER_TOKEN} \
  --name "热点报告_{period_label}" \
  --as bot)
DOC_TOKEN=$(echo "$IMPORT_JSON" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
DOC_URL="https://bluefocus.feishu.cn/docx/$DOC_TOKEN"
```

`FEISHU_HOTREPORT_FOLDER_TOKEN` 从环境变量读取，禁止硬编码。
**环境变量未设置时立即暂停，告知用户**，不要用任何兜底值继续。
（注：bot 对该文件夹仅有编辑权、非所有者 → 能在其中建文档，但**无法转移文件夹本身**；
文件夹所有权变更需由文件夹所有者操作，非本流程职责。）

### Step 4（F-3）：所有权归操作人 + 授权 admin（导入成功后立即执行）

> **授权模型（A3=② + 2026-09-22 用户指示）**：报告文档**归属发起操作人**（当前 session 的
> open_id 对应人），bot 保留 full_access 供后续更新，admin 授 full_access 便于管理。
> **不再硬编码固定 4 人清单**；需要更多人查看由操作人/admin 显式追加。

```bash
# 1) 解析操作人 open_id（正则提取，不依赖分段位置；规避 cron 会话 key 后缀）
OPERATOR_OID=$(echo "$CC_SESSION_KEY" | grep -oE 'ou_[0-9a-zA-Z]+' | head -1)
[ -z "$OPERATOR_OID" ] && { echo "❌ 无法解析操作人 open_id，暂停授权"; exit 1; }

# 2) 报告文档所有权转给操作人（--old-owner-perm full_access 让 bot 保留编辑权以便后续更新；
#    不加 --remove-old-owner。操作人 open_id 来自本 session 同一 app，不存在跨 app 错位）
lark-cli drive permission.members transfer_owner --token "$DOC_TOKEN" --type docx \
  --data "{\"member_type\":\"openid\",\"member_id\":\"$OPERATOR_OID\"}" \
  --old-owner-perm full_access --need-notification --as bot --yes

# 3) 授权 admin 便于管理（赵修源 / 袁杰松，用稳定邮箱）
for EMAIL in xiuyuan.zhao@bluefocus.com jiesong.yuan@bluefocus.com; do
  lark-cli drive +member-add --token "$DOC_TOKEN" --type docx \
    --member-type email --member-id "$EMAIL" --perm full_access --as bot --yes
done
```

任一步失败则阻塞，不进 HC3。

### Step 5（F-4）：发飞书消息

### HC3 — 飞书报告审核

触发时机：F-3 授权全部完成后（current_phase=hc3_wait）

**Step 1：spawn Validator 做规则化预检**

用 Agent tool（`model: "opus"`）spawn Validator，prompt 中只给：
- 待查文件路径：`Projects/{PROJECT_DIR}/07_报告/热点报告_{period_label}_v{N}.md`（Step 0 产出的合并报告）
- 明确指向 `Agent.Validator/KS/KS_Checklists/Topic6_热点报告检查清单.md` §HC3 作为唯一判断依据，且**仅第 1-3 条**（版块合并完整性/输出格式/内容质量）由 Validator 判断，第 4-5 条（营销案例截图、案例归类准确性）不要求 Validator 判断
- **不在 spawn prompt 里替 Validator 下结论**（禁止暗示"这份报告应该没问题"之类的倾向性描述）

Validator 执行期间会自行把结论（含"覆盖说明"）通过 IM 发到同一 chat_id（见 `Agent.Validator/CLAUDE.md` §4.6、`.claude/rules/output_formats.md` §三·bis）。

**Step 2：展示内容，等待用户回复（格式不变）**

等待 spawn 返回后，展示以下内容，等待用户回复：

```
HC3 报告人工审核

飞书文档：{DOC_URL}

权限已授予：
  xueqi.wang1@bluefocus.com
  xiuyuan.zhao@bluefocus.com
  jiesong.yuan@bluefocus.com
  jingyi.xue@bluefocus.com

通过请回复「HC3通过」；需修改请回复「HC3修改 {具体要求}」。
```

用户此时看到的是"Validator 的 IM 结论（含覆盖说明）+ 本卡片 + 等待回复"三段，而不是只有本卡片；第 4-5 条仍需人工在本环节自行核实。

通过后触发 Phase G（UI网页发布，见 `prompt/08_阶段_G网页.md`），调用外部 skill
