### Step 1：自校验

对 `07_报告/热点报告_{period_label}_v{N}.md` 逐项检查：

| 检查项 | 标准 |
|---|---|
| 章节完整性 | 4个版块标题均存在，均非空 |
| 数字来源 | 报告中出现的数字均可在 `05_合并/wide_table_full_r{N}.xlsx` 中追溯，不出现"约""估计""大概" |
| 超链接格式 | 代表热搜链接可点击，格式统一 |
| LLM 痕迹 | 不出现"综上所述""样本量充足""已按判断规则过滤"等工作透明语 |
| 执行性建议 | 不出现"建议品牌立即""应该布局"等超出洞察范畴的措辞 |
| 热度值单位 | 统一"X 分"，不出现"X 万"原始值 |

不通过：定位到具体版块 → 退回 Phase E 对应版块重跑（见 `prompt/06_阶段_E洞察.md` Step 3），不在本阶段直接改写洞察文字。

### Step 2（F-1）：确认报告文件

确认 `07_报告/热点报告_{period_label}_v{N}.md` 存在且通过 Step 1 自校验。

### Step 3（F-2）：动态创建目录并导入飞书

```bash
FOLDER_JSON=$(lark-cli drive +create-folder \
  --name "热点周报_{period_label}_{mode}" \
  --as bot)
FOLDER_TOKEN=$(printf '%s' "$FOLDER_JSON" | python3 -c \
  'import json,sys; x=json.load(sys.stdin); assert x.get("ok") is True, x; print(x.get("folder_token") or x.get("data", {}).get("folder_token") or "")')
[ -z "$FOLDER_TOKEN" ] && { echo "❌ 创建目录未返回 folder token"; exit 1; }

IMPORT_JSON=$(lark-cli drive +import \
  --file "Projects/{PROJECT_DIR}/07_报告/热点报告_{period_label}_v{N}.md" \
  --type docx \
  --folder-token "$FOLDER_TOKEN" \
  --name "热点报告_{period_label}" \
  --as bot)
DOC_TOKEN=$(printf '%s' "$IMPORT_JSON" | python3 -c \
  'import json,sys; x=json.load(sys.stdin); assert x.get("ok") is True, x; print(x.get("token") or x.get("data", {}).get("token") or "")')
DOC_URL=$(printf '%s' "$IMPORT_JSON" | python3 -c \
  'import json,sys; x=json.load(sys.stdin); assert x.get("ok") is True, x; print(x.get("url") or x.get("data", {}).get("url") or "")')
[ -z "$DOC_TOKEN" ] && { echo "❌ 导入响应缺少 doc token"; exit 1; }
[ -z "$DOC_URL" ] && { echo "❌ 导入响应缺少文档 URL"; exit 1; }
```

必须检查 JSON 的 `ok == true`，不能只看进程退出码；lark-cli 的业务错误也可能以退出码 0 返回。
`DOC_URL` 必须读取响应中的 URL 字段，禁止拼接任何固定租户域名。

### Step 4（F-3）：所有权归操作人 + 授权 admin（导入成功后立即执行）

> **授权模型（A3=② + 2026-09-22 用户指示）**：报告文档**归属发起操作人**（gateway 注入的
> `FEISHU_USER_OPEN_ID` 对应人），bot 保留 full_access 供后续更新，admin 授 full_access 便于管理。
> **不再硬编码固定 4 人清单**；需要更多人查看由操作人/admin 显式追加。

```bash
# 1) 读取 gateway 为当前任务注入的操作人 open_id
OPERATOR_OID="${FEISHU_USER_OPEN_ID:-}"
[ -z "$OPERATOR_OID" ] && { echo "❌ FEISHU_USER_OPEN_ID 未注入，暂停授权"; exit 1; }

# 2) 先给发起人 edit，确保即使后续 owner 转移失败，文档也不会成为打不开的孤儿链接。
OPERATOR_GRANT_JSON=$(lark-cli drive +member-add \
  --token "$DOC_TOKEN" --type docx \
  --member-type openid --member-id "$OPERATOR_OID" \
  --perm edit --as bot --yes)
printf '%s' "$OPERATOR_GRANT_JSON" | python3 -c \
  'import json,sys; x=json.load(sys.stdin); assert x.get("ok") is True, x; d=x.get("data") or {}; assert d.get("succeeded_count", 1) >= 1 and not d.get("partial", False), x'

# 3) 报告文档所有权转给操作人（bot 保留 full_access 供后续更新，不移除旧 owner）。
TRANSFER_JSON=$(lark-cli drive permission.members transfer_owner \
  --token "$DOC_TOKEN" --type docx \
  --data "{\"member_type\":\"openid\",\"member_id\":\"$OPERATOR_OID\"}" \
  --old-owner-perm full_access --as bot --yes)
printf '%s' "$TRANSFER_JSON" | python3 -c \
  'import json,sys; x=json.load(sys.stdin); assert x.get("ok") is True, x'

# 4) 授权 admin 便于管理（赵修源 / 袁杰松，用稳定邮箱）
for EMAIL in xiuyuan.zhao@bluefocus.com jiesong.yuan@bluefocus.com; do
  ADMIN_GRANT_JSON=$(lark-cli drive +member-add --token "$DOC_TOKEN" --type docx \
    --member-type email --member-id "$EMAIL" --perm full_access --as bot --yes
  )
  printf '%s' "$ADMIN_GRANT_JSON" | python3 -c \
    'import json,sys; x=json.load(sys.stdin); assert x.get("ok") is True, x; d=x.get("data") or {}; assert d.get("succeeded_count", 1) >= 1 and not d.get("partial", False), x'
done
```

任一步命令失败、JSON `ok != true`、批量授权 `partial == true` 或
`succeeded_count < 1` 均必须阻塞，不写 `status.f.completed`，不进 HC3。

### HC3 — 飞书报告审核



**Step 1：spawn Validator 做规则化预检**

用 Agent tool（`model: "opus"`）spawn Validator，prompt 中只给：
- 待查文件路径：`Projects/{PROJECT_DIR}/07_报告/热点报告_{period_label}_v{N}.md`（Step 0 产出的合并报告）
- 明确指向 `Agent.Validator/KS/KS_Checklists/Topic6_热点报告检查清单.md` §HC3 作为唯一判断依据，且**仅第 1-3 条**（版块合并完整性/输出格式/内容质量）由 Validator 判断，第 4-5 条（营销案例截图、案例归类准确性）不要求 Validator 判断
- **不在 spawn prompt 里替 Validator 下结论**（禁止暗示"这份报告应该没问题"之类的倾向性描述）

Validator 执行期间会自行把结论（含"覆盖说明"）通过 IM 发到同一 chat_id（见 `Agent.Validator/CLAUDE.md` §4.6、`.claude/rules/output_formats.md` §三·bis）。

**Step 2：展示内容，等待用户回复（格式不变）**

等待 spawn 返回后，展示以下内容，等待用户回复：

```
HC3 报告人工审核

飞书文档：{DOC_URL}

权限已授予：
  本次任务发起人（FEISHU_USER_OPEN_ID）
  xiuyuan.zhao@bluefocus.com
  jiesong.yuan@bluefocus.com

通过请回复「HC3通过」；需修改请回复「HC3修改 {具体要求}」。
```

用户此时看到的是"Validator 的 IM 结论（含覆盖说明）+ 本卡片 + 等待回复"三段，而不是只有本卡片；第 4-5 条仍需人工在本环节自行核实。
