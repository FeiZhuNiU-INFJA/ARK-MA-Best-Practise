## 口径同步规则（防漂移）

**口径不在本文件。** 本文件只管调度；口径在 `ks/05_四版块统计口径.md`，
而 `ks/05` 的权威又在统计脚本 docstring（`skill/insight/01_统计/e{1-4}_*.py`）。

单向同步链，只能顺着改，不能反向：

```
统计脚本 docstring（唯一真源）
  ├→ ks/05_四版块统计口径.md          人读的口径说明
  └→ 02_洞察/E{N}_*/v{N}.md            发给 LLM 的 Prompt（与 docstring 必须一致）
```

- 改数据口径：先改 `e{N}_*.py` 的实现与 docstring，再同步 `ks/05`，再检查对应 Prompt
- Prompt 升版本若改动了表格结构或数据来源，必须同一次修改里同步 docstring 与 `ks/05`
- 三方冲突时：**以代码实现为准**，不以任何文档为准

> ⚠️ **这套纪律此前失效过一次，代价是 4 项偏差。** 2026-09-20 实测发现 E1 的口径说明与代码
> 不一致（最高值 vs 中位数、5 列 vs 4 列、驱动词 vs 事件簇名、带「分」vs 裸数字），
> 而当时同一份文件开头就写着「防止与实际 Prompt 漂移」的维护规则。
>
> 漂移的那条还是 Prompt 里明文列为禁止项的
> （`E1_行业话题/v1.md:89`「禁止：表格热度值带'分'字或写最高值（口径是中位数）」）。
>
> 结论：**纪律不足以防漂移**，要靠「口径只有一处定义、其余只引用」的结构。
> 这是本轮把口径从本文件收到 `ks/05` 的原因。

### 输入

| 参数 | 路径 / 来源 |
|---|---|
| 合并宽表 | `Projects/{PROJECT_DIR}/05_合并/wide_table_full_r{N}.xlsx`（不传`--data-run-id`时自动取最新一轮） |
| 节点日历（E2依赖） | 环境变量 `MARKETING_CALENDAR_PATH` 指向的文件（外部skill `marketing-node-tagging` 提供，见 `prompt/运行前置.md`）；未设置或文件不存在则 E2 本周预告子块跳过，不阻塞其余版块 |
| 报告发布日 | 用户提供或默认今日，用于 E2 本周节点预告窗口计算（发布日~+6天）及上周/本周/远期三层分类 |
| E1-E4 活跃 Prompt 版本 | 各`02_洞察/E{N}_*/`目录下版本号最大的`v{N}.md`（只增不改，见`skill/insight/SKILL.md`「七、当前Prompt版本」） |

### 执行步骤

**Step 1：运行 pipeline_e.py（一键完成数据预处理+四路并发+落盘）**

```bash
python skill/insight/pipeline_e.py \
    --project-dir "Projects/{PROJECT_DIR}" \
    --mode full \
    --data-run-id {N} \
    --publish-date {YYYY-MM-DD}
```

内部顺序（脚本已实现，不需手动分步）：
1. `01_统计/run_stats.py --out-dir 06_洞察/v{N}/` 预处理宽表 → 产出`e{N}_data.md`（E1/E3/E4）+`e2_flags.json`（E2专属结构化数据，仅数据不含洞察）
2. 拼接「共享角色文件`_shared/role_style.md` + 版块专属Prompt」，四路并发调用 LLM
3. 保存洞察文件`06_洞察/v{N}/e{N}_v{N}.md`（该版块最终形态，含表格+洞察；每轮单独`v{N}/`子目录，不摊平在根目录）
4. 保存执行报告`06_洞察/v{N}/pipeline_e_report_v{N}.json`
5. 调用`cost_tracker.py`记录本阶段token成本

成功标志：`06_洞察/v{N}/`下出现`e1_v{N}.md`~`e4_v{N}.md`四个文件，且`pipeline_e_report_v{N}.json`中四路均无`error`字段。

**Step 2：校验四份洞察文件非空**

```bash
python -c "
from pathlib import Path
round_dir = Path('Projects/{PROJECT_DIR}/06_洞察/v{N}')
for f in ['e1_v{N}.md','e2_v{N}.md','e3_v{N}.md','e4_v{N}.md']:
    p = round_dir / f
    size = p.stat().st_size if p.exists() else 0
    print(f'{p.name}: {size} bytes', 'OK' if size > 100 else 'FAIL')
"
```

若任一文件 FAIL：进入 Step 3 单独重跑该版块；不重跑已成功的版块。

**Step 3（仅失败版块触发）：单版块重跑**

```bash
python skill/insight/pipeline_e.py \
    --project-dir "Projects/{PROJECT_DIR}" \
    --mode full \
    --publish-date {YYYY-MM-DD} \
    --skip-data-prep \
    --sections e{N}
```

`--skip-data-prep`自动定位最新一轮目录并复制`e*_data.md`/`e2_flags.json`到本轮新目录，不重新计算数据。`--sections`限定只重跑指定版块（逗号分隔ID，如`e1,e2`），Step1的统计预处理仍会照常生成全部4个版块的数据文件。

### 质量检查

| 检查项 | 标准 |
|---|---|
| 四份 insight 文件均非空 | Step 2 脚本判定 size > 100 bytes |
| 每版块含洞察段落，非纯数据表 | 人工抽查 |
| 热度值格式分版块 | E2/E4 带「分」，E1/E3 裸数字；均不出现「X 万」。口径见 `ks/05_四版块统计口径.md` |
| E3 无跨平台比较语句 | 人工抽查（根因：分数是分平台归一的，跨平台不可比，见 `ks/01_热度度量口径.md`） |
| 无"年度趋势""密集月份"等推断 | 见 `ks/06_表达规范.md` 禁止行为 |
| E4 消费洞察每条含「营销发现」启示段 | 2026-09-18 起已取消「市场策略/内容传播/公关风险」三选一框架 |
| E2 预告末尾的「补充信号」不写筹备建议 | 只讲「已有讨论」事实（v3 起已撤回独立小节，折叠为补充信号） |

不通过：定位到具体版块 → 检查该版块 Prompt 版本是否需要迭代（新建`v{N+1}.md`，不覆盖旧版，同步更新 `ks/05_四版块统计口径.md` 对应小节）→ Step 3 单版块重跑。
