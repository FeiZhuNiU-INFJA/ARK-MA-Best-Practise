## 执行步骤

按 `miaoda-web-publish` SKILL.md 的「固定执行契约」8 步执行，Topic6 专属参数如下：

1. **确认输入**：源路径 = 上表「待发布 HTML」；`status.h.app_id` 为空 → 目标=新建；
   非空 → 目标=更新该 `app_id`。进度播报 `chat_id` 取本会话 `CC_SESSION_KEY`（同 Phase G Step 3 的解析方式），
   发送身份 `--as bot`。**用户已通过「是固定关卡」的指示授权本阶段自动执行，不再逐次询问是否发布**；
   若涉及向飞书会话播报，仍按该 skill 自身规则确认消息模板。
2. **预检**：`python scripts/validate_html.py <index.html路径>`（相对该 skill 目录调用），
   有错误立即停止，报告给用户，不进入下一步。
3. **CLI 与身份检查**：`scripts/resolve_lark_cli.py` 解析可执行文件路径，全程复用同一路径；
   身份问题按该脚本指示处理，**禁止**主动清除或覆盖现有登录态。
4. **发布路由**：
   - 新建 → Git 管理流程（`+create` → `+init` → 提交 HTML → 推送 → `+release-create`），
     本地 Git 仓库落在 `Projects/{PROJECT_DIR}/09_妙搭发布/miaoda_repo/`（项目内，不落系统目录）
   - 更新 → 复用已有仓库/`app_id`，提交新 `index.html` 后 `+release-create`
5. **发布确认**：`+release-get` 轮询到 `finished`/`failed`；超时不算失败，记录 `release_id` 供人工排查。
6. **链接解析**：优先取发布响应 URL；缺失则 `+get`/`+list --keyword <应用名> --ownership mine` 按精确 `app_id` 核对，
   **不手工拼接链接**。
7. **进度播报**：Phase G 已发过"网页版已生成"通知，本阶段完成后追加一条含 `online_url` 的完成通知。
8. **结果交付**：把 `app_id` / `release_id` / `release_status` / `online_url` / 源文件 SHA-256 写回
   `run_config.yaml`（见下方 Step 更新）。

### 飞书通知

```bash
CHAT_ID=$(echo $CC_SESSION_KEY | cut -d: -f2)
lark-cli im +messages-send \
  --chat-id "$CHAT_ID" \
  --text "热点报告已发布至妙搭：{period_label}\n公网链接：{online_url}" \
  --as bot
```

非飞书会话环境下（没有 `CC_SESSION_KEY`）跳过通知，只完成 run_config 写回。
