## 1. Frame 抽取与 Entity 归一的去留

召回上它们的**独占贡献只有 5.2%**（parent_hint 1.5% + actor 精确 3.7% + object 精确 0%），
而 embedding 单通道覆盖 71.8%、独占 15.2%。Frame 又是最大单笔成本
（2805 条实测 $7.52）。`04_build_embeddings.py --text-source clean_title` 可以跑
「清洗标题直接 embed」与「Frame 拼装文本 embed」的召回对照——**这个对照至今没跑过**。

但召回不是 Frame 的全部价值，它还喂着两处，砍掉会一起断：

| 依赖 | 位置 | 没有 Frame 的后果 |
|---|---|---|
| 锚点兜底 | `07` 的 `pick_specific_entity` 在 `frames[rid]["actor"]` 上迭代 | 恒返 None，模型没给出锚点时无从兜底 |
| 事件身份核 | `identity_core` 的 actor / action / object | 全空，事件之间失去可比的身份表示 |

原先还列了第三项「跨窗口召回靠 actor_ids 交集」——**它已经断了，见第 2 条**。
所以现在砍 Frame 的实际代价比原先记录的要小，但也不能只凭召回对照就删：
锚点兜底和身份核这两项在单窗口里就有影响，得单独评估。

## 2. 跨窗口实体交集召回从未工作（缺陷）

`00_seed_from_registry.py:64` 读 `row["identity_core"]["actor_ids"]` 做历史事件与
本窗口记录的实体交集召回。`eventlib.py:241` 也读同一个字段。**但这个字段从来没有值。**

链条断在两处：

| 环节 | 应该 | 实际 |
|---|---|---|
| 03 Entity 归一 | 给每条记录算 `actor_ids` | ✅ 有（`frames["actor_ids"] = ["ENT0262"]`） |
| **07 建 identity_core** | 汇总成员的 `actor_ids` | ❌ 只写 actor / action / object / event_type |
| **09 写快照** | 把 `identity_core` 带进快照 | ❌ 整个字段都没写 |
| 00_seed 读快照 | 取 `actor_ids` | 读到空 |
| 07 用 prior_events | 拿 `actor_ids` 交集 | 恒为空集 |

实测：微博 910 条 `registry_snapshot.jsonl` 里带 `actor_ids` 的是 **0 条**，
快照实际只有 12 个字段，`identity_core` 不在其中。跨窗口召回目前只剩 `anchor_vector` 一条通道。

**只修 09 无效**，因为 `actor_ids` 上游就没生产。修它要同时动 07 和 09，
而这条路径的端到端验证（第 5 条）还没做过——**没有基准就是盲修**。
正确顺序是先跑通跨窗口增量，让这条链有验证条件，再一起修。

## 3. 平台清洗规则逐条验证

四套规则原先只依据各平台 100 条的包装统计。本次全量实跑给了第一份逐条核对，
结果是**微博规则有明确缺陷、已修，其余三平台的规则未发现问题但也未逐条核完**。

微博的问题：规则原文写着「判不准就用顿号」，导致 159 次分隔符归一里 **109 次（69%）
是误改**——把「主体 + 事项」误判成并列（`库克 华为` → `库克、华为`，实际是「库克评价华为」）。
已改成「判不准就保留原空格」，并给本地校验加了 `NEW_SEPARATOR` 拦截，
所以这一类以后会自动回退，不需要手工修。

本次实测改动率：微博 2.8%、抖音 13.4%、知乎 63.8%、B站 44.1%，整体 19.7%。
知乎和 B站 的改动率高（剥提问外壳、去装饰），抽检没发现问题，但**没有逐条核完**。

## 8. 跨题材误合并的防线

原先记录成「没有事前防线，只有事后筛查」，**这个表述过重**。`07_block_archive.py:210`
已有事前判据（「触发点明显发生在这场活动之外才独立成一级事件」），配合置信度刻度与
`member_notes` 使用。

准确的表述是：**事前判据存在但没有量化验证；事后那道网（x2）属可选层，实际会被跳过。**
本次就没跑 x2，所以净防护比文档描述的更弱。

## 9. 事件名里「加了合理但原文没有的词」抓不全

`unsourced_words()` 的 2-gram 兜底逻辑未变——`法治剧` 这类 3 字定性词能抓到，
更长的跨标点拼接串会误报，所以校验只查 ≤3 字的词。

本次量级已知：`FALLBACK_UNSOURCED` 只有 **7 条**（微博 5 + 知乎 2），全部进了
`human_review.csv`。同时 1024 条走 `SINGLETON_VERBATIM`（沿用清洗后标题，无编造风险）。

2.1.0 起 `SPLIT_FROM_EMPTY_WORD` 大幅减少（微博单平台 93 → 10 条），空词命中先重命名，
重命名过的 24 个事件标 `RENAMED_FROM_EMPTY_WORD` 并自动进 `human_review.csv`。
**人工抽检的范围是 OK 名称 + `RENAMED_FROM_EMPTY_WORD` + 剩下的拆分名**，
重命名那批优先——它们的第一个名字已经被规则拒过一次。

## 10. 阶段 03 的耗时下限

两趟改造（先全量抽实体、再统一归一）仍未实现。但**耗时口径变了**：

原先记的是「3545 条串行 25 分钟」。本次实测各平台单独耗时 12~17 分钟
（微博 16m51s / 知乎 14m52s / 抖音 12m34s / B站 12m28s），串行总和 56.8 分钟，
**四平台并行后整体墙钟 25.5 分钟**——并行把 56.8 压到 25.5，但压不进 4 分钟,
因为微博单平台就要 17 分钟。

所以「25 分钟」这个数字巧合地还对，含义却从「3545 条串行」变成
「四路并行后的墙钟下限，由最大平台封顶」。**两趟改造仍是唯一能突破 17 分钟下限的手段。**
