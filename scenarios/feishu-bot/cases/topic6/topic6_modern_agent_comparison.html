当前 Pipeline C2 细节

可以只有一个 Agent，但不能只有一段需要它完整遵循的长 Prompt。

页面比较当前实现、单 Agent 巨型 Skill、多 Agent 拆分，以及推荐的“薄 Agent + Durable Workflow”。重点不是减少文件数量，而是把阶段顺序、状态、重试和人工关卡从模型上下文移到确定性运行时。

推荐结论 对用户保持“一个 Agent、一个指令”的体验。 对系统采用持久化 DAG、无状态 Worker、版本化产物和显式人工任务。

速度优化从哪里来

Workflow 负责让优化稳定发生；真正缩短墙钟时间的是模型吞吐、DAG 并行和减少工作量。

端到端耗时的简化模型 总耗时 ≈ 必须处理的数据量 ÷ 有效模型吞吐 + 串行关键路径 + 重试与人工等待

并发上限不是越大越好。应逐档压测 4 → 8 → 16 → 32，并以 p95、429、重试率、JSON 有效率和质量确定有效上限。

推荐迁移顺序

先移动控制权，再替换算法；避免工作流和 C2 同时重写导致差异无法归因。

M1 · Durable 封装现有脚本原样变成可恢复 Task，Agent 只调用 start/status/review。
M2 · 当周去重sample 并入 full；R1-R5 多标签；统一任务执行器。
M3 · 重构 C2统一抽取、实体/向量并行、候选图、分区裁定、全局复核。
