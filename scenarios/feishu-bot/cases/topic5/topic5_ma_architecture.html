02 / MA resources

Session 挂载与 Agent 边界

业务 Session 挂载 Coordinator、Environment、只读 Memory、Vault 与 Skills。只有 Validator 通过 Multi-Agent 关系被委派，DAG owner 标签不等于独立 Agent。

Coordinator Agent

薄前台，不做业务判断、指标计算或报告撰写。

  • 启动 / resume 编排器
  • 转发可见 HC
  • 输出 FINAL_RESULT

Validator Agent

独立质检身份，只读报告与证据，不修改正文。

  • scan_report.py 全量扫描
  • 全文语义检查
  • p0_count == 0 放行

Cloud Environment

承载 Python、Node 与网络访问能力。

  • pandas / openpyxl / httpx
  • ECharts + resvg 运行时
  • Asia/Shanghai 时区

Read-only Memory

跨会话保存规范与经验，不保存运行状态。

  • /mnt/memory/topic5/MEMORY.md
  • 版本状态
  • 错误案例库

Vault

凭证只通过环境注入，文档和代码不持久化密钥。

  • Ark / SSJH / DataHub
  • 飞书应用凭证
  • 报告封面服务

Custom Skills

能力以版本化 Skill 挂载，部署脚本统一更新。

  • pipeline-orchestrator
  • SSJH / DataHub / ECharts
  • report-cover / validator

03 / Durable workflow

29 节点运行链

DAG 由 Skill 内的确定性引擎推进。节点产物、ledger 与 checkpoint 位于任务工程目录，Host SQLite 只负责跨 Session 的 Job 与 HC 状态。

04 / Gates

人工门与自动门

G3 是内部 Agent 门，必须在当前执行链内完成 Validator 委派和自动续跑，不能渲染为用户卡片。只有质检超限才升级到 HC7。

门禁类型责任主体放行条件 / 失败路径
G1 需求确认固定人工任务发起人问卷字段完整，确认后冻结需求并进入方案编制。
G2 方案确认固定人工任务发起人分析方案及能力预检通过，确认后进入生产 Run。
N10 标签策略条件人工策略自动 / 用户来源、样本、数量、唯一性和可标注性均通过则自动确认；歧义才暂停。
G3 报告质检内部自动topic5-validatorp0_count == 0 自动放行；有 P0 进入 n19 返修，禁止外溢到 Gateway。
HC7 质检升级条件人工人工处理自动返修超过 qc_max_rounds 后升级，不能豁免 P0。
G4 用户终验固定人工任务发起人对绑定 revision 的飞书文档验收；拒绝后回到交付修订。
USER_ESCALATE条件人工人工处理终验超时或异常升级，不替代用户对具体 revision 的确认。

05 / Ownership

状态、数据与交付所有权

不同存储只承担单一职责，避免把运行期事实塞进 Memory，也避免用飞书消息文本反推任务状态。

Topicx ControlStore

统一入口的控制面事实。

  • task_id 与 Router / Business Session 映射
  • 飞书话题与业务 Job 映射
  • Topic5 不使用全局 Lease

Topic5 PipelineStore

Host 侧可恢复状态。

  • pipeline_jobs
  • pipeline_hc_events
  • pipeline_receipts

Sandbox Project

单次 Run 的业务事实。

  • 节点 Artifact
  • ledger / checkpoint
  • qc_report / report_md / handoff

Memory Store

只读的跨会话规范。

  • 指标口径与版本状态
  • 历史错误案例
  • 不保存 Job / HC / OAuth 状态

外部数据源

各自保留来源边界。

  • Excel：逐帖活动明细
  • SSJH：品牌统计、基准期、词云
  • DataHub：大批量 AI 标注

飞书交付

最终报告使用原生 Docx 能力发布。

  • 原生表格与图片
  • owner transfer + readback
  • revision_id 贯穿验证与 handoff
